# SillyTavern Gotchas — ST MCP server, settings save, path-based reads. Auto-loads when working in sillytavern/.

## Gotchas

- **ST MCP server (`st`) — local stdio at `~/.local/bin/st-mcp`, source ở `sillytavern/mcp/st-mcp/`** (Python/FastMCP). Wraps 11 tools: `st_get_settings(path)`, `st_save_settings_path(path, value)`, `st_save_settings(full)`, `st_list_characters`, `st_get_character`, `st_create_character(name, fields, file_name)`, `st_merge_character(avatar, patch)`, `st_delete_character(avatar, delete_chats)`, `st_get_recent_chat`, `st_get_worldinfo`, `st_save_worldinfo`. Character write tools replace the legacy PNG tEXt-patch procedure — `st_create_character` always forces `world=""` (non-empty embeds a dead `character_book` copy) and link a lorebook after via `st_merge_character`; `st_merge_character` deepMerges (arrays REPLACE wholesale, V1/V2 field mirroring is the caller's job, `"__@@UNSET@@__"` deletes a key) and returns `"ok"` or the ST error string rather than raising on a 4xx. Registered project-scoped trong `home-server/.mcp.json` cùng civitai. **Auth: CSRF token + cookie session** — `/api/*` POSTs require `X-CSRF-Token` header from `GET /csrf-token`. Client lazy-fetches, retries 1 lần khi 403 (token rotation). Single-user mode + `SECURITYOVERRIDE=true` lets `requireLoginMiddleware` pass without basic auth. **CRITICAL save gotcha**: `/api/settings/save` writes `JSON.stringify(request.body)` directly to disk — body MUST be the bare settings dict, NOT `{"settings": <stringified>}`. Wrapping it nests `settings.settings.<actual>` in the file (corruption!). Fixed in client by sending unwrapped dict. **Token-cap gotcha**: full settings tree = 73KB → exceeds Claude's MCP output limit. ALL skill reads must be path-based (`extension_settings.sd`, `power_user.persona_descriptions`, etc. — each subtree <10KB). `st_save_settings_path` does surgical writes server-side without round-tripping the tree through Claude. Wrapper-level fields (`world_names`, `koboldai_settings`, `openai_settings`, etc.) accessible via the same path namespace via merged read view. **KEY WIN**: eliminates legacy stop-edit-start cycle trong /st-setup, /st-persona, /st-arc-save — `mcp__st__*` routes through ST's save handler (no `saveSettingsDebounced` race), ST hot-reloads automatically. /st-gen-image-prompt + /st-audit cũng path-based. Skills retain direct file ops cho operations không có API equivalent (PNG copy, expression sprite gen, chat .jsonl message body fetch). **Dotted-key gotcha:** `_get_path` / `_set_path` dùng naive `path.split(".")` → keys chứa `.` (vd `Naoko (Persona).png` trong `power_user.personas` / `power_user.persona_descriptions`) bị tách sai → tree corruption. Fix: `_parse_path` hỗ trợ bracket-escape syntax `parent.path.["literal.key"]` (dot trước bracket optional, backwards-compat với path không có `["`). Khi caller cần leaf key chứa `.`, luôn dùng bracket form (vd `persona_key = f'["{persona_avatar}"]'`). Restart Claude Code sau khi sửa server source để MCP stdio reload (editable install).
- **Persona switch = THREE fields + close the ST tab (2026-08-31):** besides the two lorebook fields below, top-level `settings.username` is `name1` (the name on every user message) — an MCP switch must write `user_avatar`, `power_user.persona_description_lorebook` AND `username`. And any ST browser tab opened before MCP settings writes will overwrite them on its next UI event (client holds the full tree; `saveSettingsDebounced`) — close/reload the tab first; files written server-side (cards, worlds, avatars) are safe. Playbook 5.47.
- **Persona lorebook has TWO fields (2026-08-30):** ST injects from the GLOBAL `power_user.persona_description_lorebook`, not from `persona_descriptions[avatar].lorebook`; only the UI persona dropdown syncs the two (`personas.js` `loadPersona`). Any MCP/script that sets `user_avatar` MUST also set the global field, or the previous persona's constants keep injecting every turn. `audit-config.py` flags the mismatch.
