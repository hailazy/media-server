# Media & Ebooks Gotchas — Homarr, Jellyfin stack, CWA/Calibre, Civitai MCP. Auto-loads when working in media/ or ebooks/.

## Gotchas

- **Homarr v1.x volume:** mount `./data:/appdata:z` (NOT `/data` — earlier wrong path wiped setup on container restart)
- **Homarr container DNS:** Forge + ST cùng `home-net` → `http://home-forge:7860` etc. Media stack ở compose network khác → reach via `host.containers.internal:PORT`
- **Bind mount ownership:** Container UIDs map through subuid; use `podman unshare` for file ops on container-owned dirs (e.g., moving model files, tar/untar backups)
- **Ebooks/CWA — PUID=0/PGID=0 cho rootless Podman + host home bind mount:** Section `ebooks/` chạy `crocodilestick/calibre-web-automated`, bind mount `/home/haint/Data/Calibre Library` (owned haint UID 1000) vào `/calibre-library`. Phải set `PUID=0`/`PGID=0` trong env — counter-intuitive nhưng đúng: container UID 0 trong rootless namespace map về host UID `haint`. Nếu set PUID=1000 → container chạy UID 1000 → maps sang subuid 525287 host-side → CWA chown library sang subuid → haint mất quyền. Pattern cùng dùng cho `media/` (linuxserver images: jellyfin, sonarr, etc.). `userns_mode: keep-id:...` KHÔNG dùng được — s6 overlay init mất CAP_SETGID trong custom userns, container không bao giờ start. Verify ownership sau start bằng `ls -la "$CALIBRE_LIBRARY_PATH" | head` — phải thấy `haint haint`. Image name phải fully-qualified `docker.io/crocodilestick/...` vì podman-compose rootless refuse short-name. Library mount mode `:z` (rw), KHÔNG `:ro` — CWA cần ghi metadata.db khi ingest.
- **Calibre Library ở `/home/haint/Data/Calibre Library`** (local btrfs, sda1) — KHÔNG phải OneDrive-synced path. `onedriver` (FUSE on-demand, không có "always keep local" pinning) làm library lớn chậm mở lần đầu nếu để trong mount OneDrive, nên tách hẳn ra ngoài. Onedriver mount tại `/home/haint/Data/OneDrive/Dev/` vẫn hiển thị `Calibre Library/` như placeholder phantom folder — KHÔNG dùng path đó, CWA chỉ biết `/home/haint/Data/Calibre Library`. Backup lên cloud qua systemd user timer `calibre-sync.timer` — daily 22:30, `rclone sync` one-way local → `onedrive-dev:Calibre Library/`. Manual sync: `systemctl --user start calibre-sync.service`.
- **Civitai MCP project-scoped:** `.mcp.json` ở root references `${CIVITAI_API_KEY}` (committable, no secret). Key sống trong `.env` (gitignored, mode 600). Env auto-loaded khi cd vào project nhờ zsh `chpwd` hook trong `~/.zshrc` — opt-in qua flag `CLAUDE_AUTOLOAD=1` ở dòng đầu `.env`. Hook reusable cho mọi project (chỉ cần thêm flag). Fallback: `./scripts/claude.sh` source `.env` rồi exec — dùng khi shell hook không available. Plain `claude` từ shell chưa load env → /doctor cảnh báo (cosmetic, MCP server vẫn auth được vì Claude Code đọc `.env` riêng cho MCP children). Skill `/civitai-model` (project-scoped tại `.claude/skills/civitai-model/`) dùng MCP để search/download/prompt-mine vào Forge paths.
- **Civitai MCP fork tracks upstream `timoncool/civitai-mcp-ultimate`** — installed package pinned tại commit `ee2577d` (`pip install --user --force-reinstall --no-deps git+https://github.com/timoncool/civitai-mcp-ultimate.git@ee2577d…`). Feature: backfill prompt khi `/api/v1/images` trả `meta=null` — refetch params từ `/api/generation/data`, khôi phục prompt-mining của `/civitai-model` (skip ảnh creator ẩn params). Upstream KHÔNG bump version trên PyPI → `pip install --upgrade` là no-op; upgrade thật = reinstall từ git ở commit mới. **Restart Claude Code** sau reinstall để MCP server (`~/.local/bin/civitai-mcp-ultimate`) respawn với code mới.
