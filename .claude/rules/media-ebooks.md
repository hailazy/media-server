# Media & Ebooks Gotchas — Homarr, Jellyfin stack, CWA/Calibre, Civitai MCP. Auto-loads when working in media/ or ebooks/.

## Gotchas

- **Homarr v1.x volume:** mount `./data:/appdata:z` (NOT `/data` — earlier wrong path wiped setup on container restart)
- **Homarr container DNS:** Forge + ST cùng `home-net` → `http://home-forge:7860` etc. Media stack ở compose network khác → reach via `host.containers.internal:PORT`
- **Bind mount ownership:** Container UIDs map through subuid; use `podman unshare` for file ops on container-owned dirs (e.g., moving model files, tar/untar backups)
- **Ebooks/CWA — PUID=0/PGID=0 cho rootless Podman + host home bind mount (2026-05-25):** Section `ebooks/` chạy `crocodilestick/calibre-web-automated`, bind mount `/home/haint/Data/Calibre Library` (owned haint UID 1000) vào `/calibre-library`. Phải set `PUID=0`/`PGID=0` trong env — counter-intuitive nhưng đúng: container UID 0 trong rootless namespace map về host UID `haint`. Nếu set PUID=1000 → container chạy UID 1000 → maps sang subuid 525287 host-side → CWA chown library sang subuid → haint mất quyền. Pattern cùng dùng cho `media/` (linuxserver images: jellyfin, sonarr, etc.). Đã thử fix bằng `userns_mode: keep-id:uid=1000,gid=1001` — fail vì s6 overlay init mất CAP_SETGID trong custom userns, container loop `s6-applyuidgid: Operation not permitted` không bao giờ start app. Trade-off PUID=0 chấp nhận được vì "container root" trong rootless = host user thường (không có host root privileges). Verify ownership sau start bằng `ls -la "$CALIBRE_LIBRARY_PATH" | head` — phải thấy `haint haint`. Image name phải fully-qualified `docker.io/crocodilestick/...` vì podman-compose rootless refuse short-name. Library mount mode `:z` (rw), KHÔNG `:ro` — CWA cần ghi metadata.db khi ingest.
